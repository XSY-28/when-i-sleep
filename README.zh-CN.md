# When I sleep 🌙

**你去睡觉，项目遇到问题也有下一步。**

睡前，你把项目拆成几个阶段，写好提示词、排好队，期待第二天起来能看到做好的东西。

凌晨两点，第二阶段的测试失败了。后面的提示词都建立在“第二阶段已经完成”之上，现在却接不上了。需要有人看报错、写修复指令、重新验收，再判断能不能进入下一阶段。

而你已经睡着了。

**When I sleep 把这段接手工作交给 agent。** 它按当前成果验收；失败时自己编写并执行修复提示词；通过后再推进有依赖的阶段。你提供项目和各阶段提示词，它在约定的范围、次数和时间内处理“做完这一步，接下来怎么办”。

## 你离开以后，它会怎么做？

假设项目分为 **数据库 → API → 界面** 三个阶段。

| 夜间发生的情况 | 技能要求 agent 采取的动作 |
| --- | --- |
| 数据库阶段验收通过 | 保存证据，开始 API 阶段。 |
| API 测试失败 | 读取错误，保存具体的修复提示词，修改实现，再运行验收。 |
| 修复后的 API 通过 | 基于已验收的结果继续做界面。 |
| 缺少必须的账户凭据 | 记录阻塞，让依赖它的阶段等待，继续明确独立的工作。 |
| Codex 剩余额度 ≤5%，且没有可用重置卡 | 暂停新的开发，整理并交付已经做出的阶段性成果。 |

**你不用半夜起来补一句“修一下”，也不用守着决定“现在能不能做下一阶段”。** 运行期间，agent 自行处理范围内可逆的选择；做不了的决定留下记录。修复次数和运行时间都有上限，避免同一个错误耗掉整晚。

跨轮续跑需要宿主的调度能力。本地运行时，电脑要保持唤醒，宿主应用要持续运行；详见[不同宿主的能力](#不同宿主的能力)。

## 第二天，你能看到什么？

已经完成的阶段、对应的验收证据，以及未完成工作的接手入口。一次遇到阻塞的运行，可以留下这样的报告，以下为**示意内容**：

```text
数据库：验收通过。
API：修复了一处请求校验问题，重新验收通过。
界面：真实账户登录验收受阻，缺少测试环境凭据。

已保存：当前改动、测试日志、API 修复提示词和 run.md。
下一步：具备测试环境凭据后，继续界面阶段的登录验收。
```

报告会告诉你：做了什么，哪些检查实际通过，卡在哪里，以及接下来怎么继续。无法运行的必要检查保持“未验证”，失败记录和剩余工作都会保留。

## 今晚怎么用

安装后，把项目和阶段提示词交给 Codex：

```text
使用 $when-i-sleep。
项目：/path/to/my-project
各阶段提示词：docs/stages.md
自动验收、失败修复、通过后继续推进。
我离开期间不要向我提问。
```

也可以直接粘贴各阶段提示词，不必先写成文件。其他支持 skill 的宿主，按它自己的语法调用 **When I sleep**。

## 安装

### Codex

让内置 skill installer 安装：

```text
$skill-installer 安装这个 skill：
https://github.com/XSY-28/when-i-sleep/tree/main/skills/when-i-sleep
```

Codex 会自动识别已安装的技能；没有出现时重启 Codex。参见[官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

### 其他 Agent Skills 宿主

下载或克隆本仓库，把完整的 [`skills/when-i-sleep`](skills/when-i-sleep) 目录放进宿主配置的技能位置。保留 `SKILL.md` 旁边的 `references/` 和 `assets/`；`agents/` 中的 OpenAI 界面元数据在其他宿主中可忽略。

更新既有安装前先备份本地修改。不同宿主的目录和调用语法有所不同，以它的文档为准。

## 不同宿主的能力

| 运行环境 | 阶段验收与修复 | 离开后的续跑 | 账户额度重置 |
| --- | --- | --- | --- |
| 暴露了所需桌面工具的 Codex | 通用技能流程 | 使用实际可用的原聊天 heartbeat | 只使用已有卡，逐次明确授权 |
| 缺少这些工具的 Codex | 通用技能流程 | 在当前轮推进，结束前保存恢复入口 | 工具不可用时不启用 |
| 其他接受 `SKILL.md` 的宿主 | 可移植指令，尚未逐个实机验证 | 只使用该宿主实际支持的调度机制 | 不启用 |

**判断依据是实际运行宿主，不是模型名称。** 在其他 agent 中调用 OpenAI 模型，不会启用 Codex 分支；其他宿主不加载 Codex 的账户操作说明。

技能使用宿主实际提供的续跑工具和权限。Codex 的原生续跑能力参见[官方定时任务文档](https://developers.openai.com/codex/app/automations)。安装技能本身不会创建后台服务。

## Codex 额度只剩 5% 时

最后一点额度，要留给一份能接着用的成果。相关核心五小时或每周窗口的剩余额度 **≤5%** 时，Codex 分支会先保存 `checkpoint.md`，再尝试重置。

工具可用、且本次有明确的单次兑换授权时，可以尝试使用一张已有重置卡。**没有可用卡，就整理已完成内容、当前改动、验收结果、阻塞和下一步，暂停新的开发。** 确认额度恢复后，可以在原运行时限内继续。

需要授权一次条件兑换时，在**本次运行请求**中加上：

```text
本次运行额度剩余 ≤5% 时，授权使用一张已有重置卡。
```

这一分支仅用于 Codex，其他宿主不加载账户重置指令。每次兑换遵守宿主授权要求，只使用已有卡；恢复和重复请求的处理规则见 [Codex 适配说明](skills/when-i-sleep/references/codex.md)。

## 调整运行预算

| 设置 | 默认值 |
| --- | --- |
| 有调度能力时的唤醒间隔 | 15 分钟 |
| 修复轮数 | 每阶段 3 轮 |
| 阶段经过时间上限 | 2 小时 |
| 整次运行时间上限 | 8 小时 |

可以在调用时覆盖。通过后同一轮立即继续，15 分钟是续跑间隔；唤醒不会重置计数。

项目需要不同上限时，在同一条请求里说明即可。发布、部署、购买或外部消息仍须已有授权。

## 试一个小项目

仓库提供了一个[故意写错的购物车示例](examples/cart/STAGES.md)。把 `examples/cart/` 复制到可丢弃的工作目录，再让技能执行里面的 `STAGES.md`。示例本身只需要 Python 3，不需要账户、API key 或安装第三方包。

预期流程：发现总价计算错误 → 保存并执行修复 → 固定验收通过 → 新增收据函数并验收。先在这个小项目中查看执行记录，再安排较大的夜间任务。

## 已检查到什么程度

包检查和购物车示例可以按[验证说明](docs/validation.md)复现，覆盖打包完整性与固定验收行为。真实整夜运行的可靠性、重置卡兑换、崩溃恢复和其他宿主执行，仍需要对应的集成验证。
