# When I sleep 🌙

**把你离开的这段时间，也安排进项目计划。**

一个用于分阶段开发的 agent skill：**验收当前阶段，失败就修复，通过后继续推进。** 留下项目和阶段提示词，回来查看已经完成的成果，或一份说明卡在哪里、下一步怎么继续的阶段报告。

[English](README.md) · [安装](#安装) · [试一个小项目](#试一个小项目) · [不同宿主的能力](#不同宿主的能力)

```text
阶段提示词 → 执行 → 验收 → 通过 → 下一个就绪阶段
                    ↓ 失败
                 保存修复提示词
                    ↓
                 修复 → 重新验收

缺少必要能力、预算用尽或额度不足 → 整理阶段性成果与恢复入口
```

## 直接使用

在 Codex 安装后发送：

```text
使用 $when-i-sleep。
项目：/path/to/my-project
各阶段提示词：docs/stages.md
自动验收、失败修复、通过后继续推进，不向我提问。
```

其他支持 skill 的宿主，按它自己的调用方式选择 **When I sleep**。阶段提示词也可以直接粘贴到聊天里。

这套流程会指导 agent：

- **验收后再推进。** 用当前文件运行检查，未提交的修改也必须纳入证据。
- **把失败变成下一项工作。** 保存包含真实错误、修改范围和复验命令的修复提示词，再执行修复。
- **继续能做的工作。** 保留阻塞，不跳过依赖；明确独立的阶段可以继续。
- **留下一份可接手的成果。** 保存交付文件、阶段结论、证据、剩余预算和下一步。
- **留住最后的额度。** Codex 剩余额度 **≤5%** 时先保存成果；没有可用重置卡，就交付阶段报告并暂停新的开发。

运行期间不提问。超出已有授权范围的决定会记录为阻塞；验收标准保持不变，修复有次数和时间上限。

## 安装

### Codex

让内置 skill installer 安装：

```text
$skill-installer 安装这个 skill：
https://github.com/XSY-28/when-i-sleep/tree/main/skills/when-i-sleep
```

Codex 会自动识别已安装的技能；没有出现时重启 Codex。参见[官方技能文档](https://learn.chatgpt.com/docs/build-skills)。

### 其他 Agent Skills 宿主

下载或克隆本仓库，把完整的 [`skills/when-i-sleep`](skills/when-i-sleep) 目录放进宿主配置的技能位置。保留 `SKILL.md` 旁边的 `references/` 和 `assets/`；`agents/` 中的 OpenAI 界面元数据在其他宿主中可忽略。

更新既有安装前先备份本地修改。不同宿主的目录和调用语法有所不同，以它的文档为准。

## 不同宿主的能力

| 运行环境 | 阶段验收与修复 | 离开后的续跑 | 账户额度重置 |
| --- | --- | --- | --- |
| 暴露了所需桌面工具的 Codex | 通用技能流程 | 使用实际可用的原聊天 heartbeat | 只使用已有卡，逐次明确授权 |
| 缺少这些工具的 Codex | 通用技能流程 | 在当前轮推进，结束前保存恢复入口 | 工具不可用时不启用 |
| 其他接受 `SKILL.md` 的宿主 | 可移植指令，尚未逐个实机验证 | 只使用该宿主实际支持的调度机制 | 不启用 |

**判断依据是实际运行宿主，不是模型名称。** 在其他 agent 中调用 OpenAI 模型，不会启用 Codex 分支；其他宿主不加载 Codex 的账户操作说明。

技能本身是指令包，不会安装后台服务，也不能让已经关闭的应用继续工作。本地无人值守续跑需要宿主持续运行、项目可访问、权限适合执行，并让电脑保持唤醒。Codex 的原生续跑能力参见[官方定时任务文档](https://developers.openai.com/codex/app/automations)。

## Codex 额度只剩 5% 时

任一已知、相关的核心五小时或每周窗口，剩余 **≤5%** 即触发；未知值不当成零。

1. 先保存当前状态和可阅读的 `checkpoint.md`，留住已经完成的工作。
2. 工具可用且本次有一份明确的单次兑换授权时，尝试使用一张已有重置卡。
3. 没有可用卡时，立即整理并交付阶段性成果，暂停新的开发。报告包括已完成内容、当前改动、检查结果、阻塞、运行中操作和下一步。
4. 确认重置成功后继续；否则只在原运行时限内按已知恢复时间续跑，或保留 checkpoint 结束。

需要授权一次条件兑换时，在**本次运行请求**中加上：

```text
本次运行额度剩余 ≤5% 时，授权使用一张已有重置卡。
```

不购买额度。每次兑换遵守宿主授权要求，示例和旧运行不能为新兑换授权；结果不确定时沿用同一请求编号，避免重复消费。详见 [Codex 适配说明](skills/when-i-sleep/references/codex.md)。

## 调整运行预算

| 设置 | 默认值 |
| --- | --- |
| 有调度能力时的唤醒间隔 | 15 分钟 |
| 修复轮数 | 每阶段 3 轮 |
| 阶段经过时间上限 | 2 小时 |
| 整次运行时间上限 | 8 小时 |

可以在调用时覆盖。通过后同一轮立即继续，15 分钟是续跑间隔；唤醒不会重置计数。

运行保留唯一权威状态 `run.md`、原始阶段提示词、修复提示词、验收日志及必要的阶段报告。离开期间不要求你回复；发布、部署、购买或外部消息仍须已有授权。

## 试一个小项目

仓库提供了一个[故意写错的购物车示例](examples/cart/STAGES.md)。把 `examples/cart/` 复制到可丢弃的工作目录，再让技能执行里面的 `STAGES.md`。示例本身只需要 Python 3，不需要账户、API key 或安装第三方包。

预期流程：发现总价计算错误 → 保存并执行修复 → 固定验收通过 → 新增收据函数并验收。先在这个小项目中查看执行记录，再安排较大的夜间任务。

## 已检查到什么程度

包检查验证元数据、完整引用、本地文档链接、私人路径泄漏，并检查账户操作只出现在 Codex 适配文件中。可复现的示例检查确认错误实现会失败、正确行为会通过。

这些检查**不证明**真实整夜续跑、真实重置卡兑换、崩溃恢复或所有宿主兼容性。具体检查命令与范围见[验证说明](docs/validation.md)。
